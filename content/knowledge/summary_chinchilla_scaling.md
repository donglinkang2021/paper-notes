# Training Compute-Optimal Large Language Models (Chinchilla)

**论文**: Training Compute-Optimal Large Language Models
**作者**: Jordan Hoffmann*, Sebastian Borgeaud*, Arthur Mensch*, 等 (DeepMind)
**arXiv**: 2203.15556 (2022)

## 核心发现

**当前大型语言模型严重训练不足**。给定计算预算，模型大小和训练 token 数应该**等比例增长**：每当模型大小翻倍时，训练数据量也应该翻倍。

这与 Kaplan et al. (2020) 的建议相矛盾，后者建议主要增加模型大小。

## 问题背景

### 当前 LLM 的现状

| 模型 | 参数量 | 训练 Token 数 |
| --- | --- | --- |
| LaMDA | 137B | 168B |
| GPT-3 | 175B | 300B |
| Jurassic | 178B | 300B |
| Gopher | 280B | 300B |
| MT-NLG | 530B | 270B |
| **Chinchilla** | **70B** | **1.4T** |

**观察**: 除 LaMDA 外，大多数模型都训练约 300B tokens，尽管模型大小差异很大。

### 核心问题

给定固定的 FLOPs 预算 $C$，如何最优地权衡模型大小 $N$ 和训练 token 数 $D$？

$$N_{\text{opt}}(C), D_{\text{opt}}(C) = \arg\min_{N, D \text{ s.t. } \text{FLOPs}(N, D) = C} L(N, D)$$

## 三种分析方法

### 方法 1：固定模型大小，变化训练步数

训练从 70M 到 10B 参数的模型，每个模型训练 4 种不同的 token 数量。

**过程**:
1. 对每个 (N, D) 组合，获得训练损失曲线
2. 对于每个 FLOP 预算，找到达到最低损失的模型
3. 拟合幂律关系

**结果**: $N_{\text{opt}} \propto C^{0.50}$, $D_{\text{opt}} \propto C^{0.50}$

### 方法 2：IsoFLOP 分析

对于 9 个固定的 FLOP 预算（$6 \times 10^{18}$ 到 $3 \times 10^{21}$），变化模型大小。

**过程**:
1. 对每个 FLOP 预算，画出最终损失 vs 参数量的曲线
2. 用抛物线拟合找到最小损失对应的模型大小
3. 拟合幂律关系

**结果**: $N_{\text{opt}} \propto C^{0.49}$, $D_{\text{opt}} \propto C^{0.51}$

### 方法 3：参数化损失函数拟合

基于风险分解，提出损失函数的参数化形式：

$$\hat{L}(N, D) = E + \frac{A}{N^\alpha} + \frac{B}{D^\beta}$$

其中：
- $E$: 理想生成过程的损失（自然文本的熵）
- $A/N^\alpha$: 有限参数导致的近似误差
- $B/D^\beta$: 有限数据导致的优化误差

**最小化 Huber 损失**:

$$\min_{A, B, E, \alpha, \beta} \sum_{\text{Runs } i} \text{Huber}_\delta(\log \hat{L}(N_i, D_i) - \log L_i)$$

**结果**: $N_{\text{opt}} \propto C^{0.46}$, $D_{\text{opt}} \propto C^{0.54}$

拟合参数：$E = 1.69$, $A = 406.4$, $B = 410.7$, $\alpha = 0.34$, $\beta = 0.28$

## 缩放系数对比

| 方法 | $a$ ($N_{\text{opt}} \propto C^a$) | $b$ ($D_{\text{opt}} \propto C^b$) |
| --- | --- | --- |
| 方法 1 | 0.50 | 0.50 |
| 方法 2 | 0.49 | 0.51 |
| 方法 3 | 0.46 | 0.54 |
| **Kaplan et al. (2020)** | **0.73** | **0.27** |

**关键差异**: Kaplan 建议计算增加 10 倍时，模型增大 5.5 倍、数据仅增加 1.8 倍；本文发现应该等比例增加。

### 与 Kaplan et al. 差异的原因

1. **学习率调度**: Kaplan 对所有模型使用固定的训练 token 数和学习率调度，无法建模这些超参数对损失的影响
2. **模型规模**: 本文包含最多 16B 参数的模型，而 Kaplan 主要使用小于 100M 的模型
3. **曲率效应**: 本文观察到 FLOP-损失前沿存在轻微曲率

## 计算最优模型预测

| 参数量 | 最优 FLOPs | 最优训练 Token 数 |
| --- | --- | --- |
| 400M | $1.92 \times 10^{19}$ | 8.0B |
| 1B | $1.21 \times 10^{20}$ | 20.2B |
| 10B | $1.23 \times 10^{22}$ | 205.1B |
| 67B | $5.76 \times 10^{23}$ | 1.5T |
| 175B | $3.85 \times 10^{24}$ | 3.7T |
| 280B | $9.90 \times 10^{24}$ | 5.9T |
| 1T | $1.27 \times 10^{26}$ | 21.2T |

**重要结论**:
- 175B 参数模型需要训练 4.2T tokens 才是计算最优
- 280B 的 Gopher 级模型需要训练 6.8T tokens
- 除非有 $10^{26}$ FLOPs（250 倍 Gopher 的计算量），否则 1T 参数模型不太可能是最优选择

## Chinchilla 模型

### 设计理念

基于分析，对于 Gopher 的计算预算，最优模型应该是 40-70B 参数。选择训练 70B 参数的模型，使用 1.4T tokens。

### 架构对比

| 参数 | Gopher (280B) | Chinchilla (70B) |
| --- | --- | --- |
| 层数 | 80 | 80 |
| 注意力头数 | 128 | 64 |
| Key/Value 大小 | 128 | 128 |
| $d_{\text{model}}$ | 16,384 | 8,192 |
| 最大学习率 | $4 \times 10^{-5}$ | $1 \times 10^{-4}$ |
| 批大小 | 3M → 6M | 1.5M → 3M |

### 训练改进

- 使用 AdamW 而非 Adam
- 修改的 SentencePiece tokenizer（不使用 NFKC 归一化）
- 前向/后向使用 bfloat16，优化器状态使用 float32

## 实验结果

### 语言建模

Chinchilla 在 The Pile 的所有子集上都显著优于 Gopher。

WikiText-103 困惑度：
- Gopher: 7.75
- Chinchilla: **7.16**

| 随机 | 25.0% |

## 核心贡献

1. **重新审视缩放定律**: 发现模型大小和训练数据应等比例增长
2. **三种分析方法**: 提供多种可复现的方法来估计最优分配
3. **Chinchilla 模型**: 用 70B 参数和 1.4T tokens 验证理论，在几乎所有任务上超越 280B 的 Gopher
4. **推理效率**: 更小的模型意味着更低的推理成本和更容易的下游部署

## 局限性

1. **大规模验证有限**: 只有 Chinchilla 和 Gopher 两个可比的大规模训练运行
2. **幂律假设**: 假设计算前沿可以用幂律描述，但观察到高计算预算时存在凹性
3. **单 epoch 训练**: 所有训练运行都使用少于一个 epoch 的数据
4. **余弦调度假设**: 假设最优训练的余弦周期长度应与训练步数匹配

## 重要启示

### 数据比模型更重要

- 当前 LLM 的数据量远远不够
- 175B 模型需要 4.2T tokens，远超当前使用的 300B
- **高质量数据集的收集变得至关重要**

### 更大的数据集需要更多关注

- 训练万亿 tokens 带来伦理和隐私问题
- 大规模网络爬取数据包含有毒语言、偏见和隐私信息
- 数据集审查比以往更加重要

### 实际影响

- 更小的模型意味着更低的推理成本
- 更容易在较小硬件上部署
- 能源成本在推理和微调时被摊销

## 余弦调度长度的重要性

当余弦周期长度超过目标训练步数 25% 以上时，性能明显下降。最优训练应将余弦周期长度与最大训练步数匹配。

## 其他数据集的一致性

在 C4 和 GitHub 代码数据集上的 IsoFLOP 分析显示类似的缩放行为：

| 数据集 | $a$ | $b$ |
| --- | --- | --- |
| C4 | 0.50 | 0.50 |
| GitHub | 0.53 | 0.47 |

这表明结果与数据集无关，只要不训练超过一个 epoch。
