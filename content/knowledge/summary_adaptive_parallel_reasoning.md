# 学习自适应并行推理：让语言模型自主编排串行与并行计算

## 核心贡献

本文提出 **Adaptive Parallel Reasoning (APR)**，一种让语言模型在推理时自适应地编排串行和并行计算的框架。核心思想借鉴操作系统的多线程机制：模型在推理过程中可以通过 `spawn()` 操作派生子线程进行并行探索，子线程通过 `join()` 将结果返回父线程。

关键创新：
1. **父子线程推理机制**：模型在解码过程中自主决定何时、如何派生并行子线程，子线程独立探索不同推理路径，仅返回成功结果给父线程
2. **端到端强化学习优化**：不仅用监督学习初始化，还通过 GRPO 端到端优化整个并行推理策略，让模型学会最优的计算资源分配
3. **突破上下文窗口瓶颈**：将搜索分布到多个线程中，每个线程只需部分上下文，从而在固定上下文窗口下实现更大规模的搜索

## 方法详解

### 多线程推理机制

**spawn() 操作**：
- 父线程在解码过程中可随时调用 `spawn(msgs)`，其中 `msgs` 是一组字符串，每个字符串作为一个子线程的初始上下文
- 父线程通过给不同子线程传递不同上下文来实现协调，避免了 self-consistency 等方法中独立采样缺乏协调的问题

**join() 操作**：
- 子线程完成推理后生成 `join(msg)` 终止执行，将结果返回父线程
- 子线程自主决定返回什么信息——在 Countdown 任务中，仅返回成功的解题路径，丢弃中间搜索痕迹
- 所有子线程终止后，父线程继续解码，上下文仅包含之前的内容加上子线程返回的消息

**与现有方法的统一**：
- 纯串行 CoT = APR 不使用 spawn（0 个子线程）
- Self-consistency = 多个独立线程，无协调
- Tree-of-Thought = 固定的手工设计搜索结构
- APR = 模型自主学习的自适应并行结构

### 训练流程

**第一阶段：监督学习初始化**

- 使用 Llama2 架构从头训练 228M 参数模型（非预训练模型），4096 token 上下文窗口
- 基于符号求解器生成 50 万条训练轨迹
- 开发了**混合搜索**（hybrid search）策略，在同一搜索轨迹中混合 DFS 和 BFS，比纯 DFS 或纯 BFS 效果更好
- 两种符号求解器：SoS+（串行混合搜索）和 APR（带并行化的混合搜索）

**第二阶段：强化学习端到端优化**

- 使用 GRPO 算法进行策略优化
- 奖励信号：解题是否正确（二值奖励）
- 模型在 RL 阶段学会策略性地决定何时、如何、以多大规模调用子线程
- RL 的核心收益来自**学会分配更多测试时计算**（更多子线程），而非在固定计算预算下做出更优决策

### 任务设置：Countdown

给定 4 个数字和一个目标数，用四则运算使每个数字恰好使用一次，得到目标值。例如：给定 {1,4,6,8}，目标 10，解为 $(8-6)\times(4+1)=10$。

## 实验结果

### 主要性能对比

| 指标 | SoS+（串行） | APR（并行） |
|------|-------------|------------|
| 相同上下文窗口（4k）准确率 | 60.0% | **83.4%** |
| 相同总计算量（20k tokens）准确率 | 66.6% | **80.1%** |
| 相同延迟（~5000ms）准确率 | 57.3% | **75.2%** |

### 计算扩展性

- 在低计算量区间（<4k tokens），APR 因"并行化开销"（线程编排 token）略逊于串行方法
- 随着计算量增加，APR 显著超越串行方法，在 20k tokens 时绝对提升 13.5%
- APR 用 57.4% 更少的计算量即可匹配 SoS+ pass@8 的性能

### 上下文窗口利用效率

- 仅 3 个子线程时，APR 在所有窗口大小下已超越 SoS+
- 6 或 10 个子线程时，在 4k 窗口下分别高出约 10% 和 20%
- 核心优势：将推理分布到多个线程，避免将整个搜索轨迹塞入单一上下文窗口

### 强化学习的效果

- RL 将 APR 准确率从 75.5% 提升至 83.4%（+7.9%）
- 对比：RL 仅将 SoS+ 从 57.3% 提升至 60.0%（+2.7%）
- RL 后模型行为变化：平均序列长度从 1471 增至 1796 tokens（+22.1%），子线程数从 6.1 增至 8.2（+34.4%）
- **关键发现**：RL 的主要收益来自学会扩展测试时计算（更宽的搜索），而非提升固定预算下的决策质量。当强制使用最大子线程数（10 个）时，RL 前后准确率几乎不变（83.2% vs 83.3%）

### 延迟效率

- 利用 SGLang 框架的连续批处理和 radix attention 实现高效并行推理
- 在 8 GPU（NVIDIA RTX A6000）部署场景下，1 个 GPU 处理主线程，其余处理子线程
- 在相同延迟约束下，APR 准确率显著高于串行方法

## 与其他方法的对比

| 方法 | 搜索结构 | 是否端到端优化 | 线程间协调 | 上下文效率 |
|------|---------|--------------|-----------|-----------|
| Chain-of-Thought | 串行 | 否 | N/A | 低（受窗口限制） |
| Self-Consistency | 并行独立 | 否 | 无 | 低（重复计算） |
| Tree-of-Thought | 固定树结构 | 否 | 手工设计 | 中 |
| PASTA（并发工作） | 并行子任务 | 否 | 有，但合并完整上下文 | 低 |
| Hogwild! Inference（并发工作） | 并行工作线程 | 否（仅 prompting） | 有 | 中 |
| **APR（本文）** | **自适应并行** | **是（SL + RL）** | **学习得到** | **高** |

**APR 的独特优势**：
- 搜索结构由模型自主学习，而非人工设计
- 子线程仅返回精炼结果，不将完整上下文合并回父线程
- 端到端 RL 优化整个并行策略，包括何时 spawn、spawn 多少、传递什么上下文

## 局限性

1. **仅在非预训练模型上实验**：当前实验使用从头训练的 228M 模型，未在预训练语言模型上验证
2. **仅限 Countdown 任务**：未扩展到通用推理任务（数学、代码、自然语言推理等）
3. **依赖监督学习初始化**：需要符号求解器生成训练数据进行 bootstrap，未探索纯 RL 训练（如 R1-Zero 风格）
4. **通信协议简单**：仅使用 fork/join 操作，未探索更复杂的线程间通信模式（如 any-to-any 消息传递、发布-订阅模式）
5. **RL 收益主要来自计算分配**：RL 并未显著提升固定计算预算下的推理质量，主要是学会了使用更多计算资源

## 关键洞察

1. **并行化是推理扩展的新维度**：传统方法只能通过加长序列（更深的搜索）来扩展计算，APR 增加了"更宽的搜索"这一维度，且不受上下文窗口限制
2. **模型可以学会自主编排计算**：通过 RL，模型不仅学会解题，还学会了如何分配计算资源——这是一种元层次的能力
3. **宽搜索优于深搜索**：在 Countdown 任务上，RL 发现更宽的搜索（更多子线程）比更深的搜索（更长序列）更有效，子线程数增长（+34.4%）远超序列长度增长（+22.1%）
4. **上下文窗口是串行推理的根本瓶颈**：串行方法的性能受限于上下文窗口大小，而并行方法通过分布式搜索绕过了这一限制
5. **并行化开销可被规模化摊销**：虽然线程编排引入额外 token 开销，但随着计算预算增加，并行方法的收益远超开销
6. **从操作系统到推理系统的类比**：多线程、fork/join、前缀共享等系统概念可以自然地迁移到语言模型推理中，暗示更多系统级优化的可能性

**未来方向**：
- 扩展到预训练语言模型和通用推理任务
- 探索纯 RL 训练（去除监督学习依赖）
- 设计更丰富的线程间通信协议（all-to-all、订阅模式等）
