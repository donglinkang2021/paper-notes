# ReAct: Synergizing Reasoning and Acting in Language Models

**论文信息**
- 标题: ReAct: Synergizing Reasoning and Acting in Language Models
- 作者: Shunyu Yao (Princeton), Jeffrey Zhao, Dian Yu, Nan Du, Izhak Shafran, Karthik Narasimhan, Yuan Cao (Google Brain)
- 发表: ICLR 2023
- arXiv: [2210.03629](https://arxiv.org/abs/2210.03629)
- 项目主页: https://react-lm.github.io/

---

## 核心思想

ReAct 提出了一个简单而有效的范式：让大型语言模型(LLM)交替生成**推理轨迹(reasoning traces)**和**任务特定动作(task-specific actions)**，实现推理与行动的协同：

- **推理支持行动**: 推理轨迹帮助模型分解目标、跟踪进度、处理异常、调整计划
- **行动支持推理**: 通过与外部环境交互获取额外信息，为推理提供支撑

## 方法框架

### 问题设定

在时间步 $t$，智能体接收观察 $o_t \in \mathcal{O}$，基于策略 $\pi(a_t \mid c_t)$ 执行动作 $a_t \in \mathcal{A}$，其中上下文：

$$c_t = (o_1, a_1, \cdots, o_{t-1}, a_{t-1}, o_t)$$

### ReAct 的核心改进

将动作空间扩展为：

$$\hat{\mathcal{A}} = \mathcal{A} \cup \mathcal{L}$$

其中 $\mathcal{L}$ 是语言空间。语言空间中的动作 $\hat{a}_t \in \mathcal{L}$ 称为**思考(thought)**或**推理轨迹(reasoning trace)**：
- 不影响外部环境，不产生观察反馈
- 通过对当前上下文 $c_t$ 进行推理，组合有用信息
- 更新上下文 $c_{t+1} = (c_t, \hat{a}_t)$ 以支持未来的推理或行动

### 思考的多种用途

1. **分解任务目标**，创建行动计划
2. **注入常识知识**
3. **从观察中提取重要信息**
4. **跟踪进度**，转换行动计划
5. **处理异常**，调整行动计划

### 实现方式

使用冻结的大型语言模型(PaLM-540B)，通过少样本上下文示例进行提示：
- 每个示例是人类标注的轨迹，包含动作、思考和环境观察
- **知识密集型任务**: 交替生成思考和动作(密集思考)
- **决策任务**: 思考稀疏出现在轨迹的关键位置

## 实验评估

### 1. 知识密集型推理任务

#### 数据集
- **HotPotQA**: 多跳问答，需要对多个Wikipedia段落进行推理
- **FEVER**: 事实验证，判断声明是 SUPPORTS/REFUTES/NOT ENOUGH INFO

#### 动作空间设计

简单的Wikipedia API：
- `search[entity]`: 返回实体页面的前5句话
- `lookup[string]`: 返回页面中包含该字符串的下一句话
- `finish[answer]`: 完成任务并给出答案

#### 基线方法

| 方法 | 描述 |
|------|------|
| Standard | 移除所有思考、动作、观察 |
| CoT | 只保留推理，移除动作和观察 |
| CoT-SC | CoT + 自一致性(采样21条轨迹，多数投票) |
| Act | 移除思考，只保留动作 |

#### 结果 (PaLM-540B)

| 方法 | HotPotQA | FEVER |
|------|----------|-------|
| Standard | 25.7 | 50.0 |
| CoT | 29.4 | 56.3 |
| CoT-SC (n=21) | 33.4 | 60.4 |
| Act | 25.7 | 58.9 |
| **ReAct** | **27.4** | **60.9** |
| ReAct → CoT-SC | **35.1** | 64.6 |
| CoT-SC → ReAct | 32.3 | **67.5** |

#### 关键发现

**A) 幻觉问题**: CoT 的假阳性率远高于 ReAct (14% vs 6%)，幻觉是 CoT 的主要失败模式(56%)

**B) 结构约束的代价**: ReAct 交替推理-动作-观察的结构虽提高了可信度，但也降低了推理的灵活性

**C) 搜索质量关键**: 对 ReAct 而言，成功检索有信息价值的知识至关重要，23% 的错误源于非信息性搜索

#### 组合策略

- **ReAct → CoT-SC**: ReAct 在给定步数内无法给出答案时，回退到 CoT-SC
- **CoT-SC → ReAct**: 多数答案置信度低时(出现次数 < n/2)，回退到 ReAct

### 2. 决策任务

#### ALFWorld (文本游戏)

- 6种任务类型，需要导航和交互
- 任务可能有50+位置，专家策略需要50+步骤
- 需要常识推理确定物品位置

**结果:**

| 方法 | 平均成功率 |
|------|-----------|
| BUTLER (IL, 10^5 轨迹) | 37% |
| Act | 45% |
| ReAct-IM | 53% |
| **ReAct** | **71%** |

#### WebShop (网页导航)

- 1.18M 真实商品，12k 人类指令
- 根据用户需求购买商品
- 包含结构化和非结构化文本

**结果:**

| 方法 | 平均分数 | 成功率 |
|------|----------|--------|
| IL | 59.9 | 29.1% |
| IL + RL | 62.4 | 28.7% |
| Act | 62.3 | 30.1% |
| **ReAct** | **66.6** | **40.0%** |
| 人类专家 | 82.1 | 59.6% |

### 3. 微调实验

在 HotPotQA 上使用3000条正确轨迹进行微调：

- **提示学习**: ReAct 在 PaLM-8/62B 上表现最差(难以从少量示例学习推理+行动)
- **微调后**: ReAct 成为最佳方法
  - PaLM-8B 微调 ReAct 超过所有 PaLM-62B 提示方法
  - PaLM-62B 微调 ReAct 超过所有 PaLM-540B 提示方法

## ReAct vs Inner Monologue

Inner Monologue (IM) 的"内心独白"仅限于：
- 观察环境状态
- 描述需要完成的子目标

**ReAct 的优势:**
- 思考空间更灵活、更稀疏
- 支持多种推理类型
- 能进行高层目标分解
- 能利用常识知识

实验表明 ReAct 显著优于 IM 风格提示 (71% vs 53%)。

---

## 核心优势

| 特性 | 描述 |
|------|------|
| **直观易设计** | 标注者只需在动作上添加自然语言思考 |
| **通用灵活** | 适用于不同动作空间和推理需求的多种任务 |
| **性能鲁棒** | 仅用1-6个示例就能超越基线 |
| **人类对齐可控** | 可解释的决策过程，支持人类检查和编辑 |

---

## Human-in-the-Loop

ReAct 支持人机协作：
- 人类可以检查和编辑推理轨迹
- 通过修改几个思考就能显著改变模型行为
- 比直接输入动作更高效

---

## 局限性与未来方向

1. **上下文长度限制**: 复杂任务需要更多示例，但受限于输入长度
2. **搜索质量**: 检索失败会严重影响后续推理
3. **推理错误**: 模型可能陷入重复生成相同思考和动作的循环

**未来方向:**
- 使用更多高质量人类标注数据进行微调
- 多任务训练扩展 ReAct
- 与强化学习结合

## 与本仓库的关联

ReAct 范式与 Claude Code 的工作方式高度相关：
- Claude Code 在执行任务时也是交替进行推理(思考下一步做什么)和行动(调用工具)
- 这种"思考-行动"循环使得 AI 助手能够处理复杂的多步骤任务
- ReAct 的人机协作理念也体现在 Claude Code 允许用户介入和引导的设计中
