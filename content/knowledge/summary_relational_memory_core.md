# Relational Recurrent Neural Networks

**论文**: Relational recurrent neural networks
**作者**: Adam Santoro*, Ryan Faulkner*, David Raposo*, Jack Rae, Mike Chrzanowski, Théophane Weber, Daan Wierstra, Oriol Vinyals, Razvan Pascanu, Timothy Lillicrap (DeepMind)
**arXiv**: 1806.01822 (2018, NeurIPS 2018)

## 核心问题

基于记忆的神经网络（如 LSTM、记忆增强神经网络）擅长**存储和检索**信息，但是否擅长对记忆中的信息进行**关系推理**？

**核心假设**: 现有模型缺乏显式的记忆交互偏置，可能限制了其进行时序关系推理的能力。

## 关系推理的定义

**关系推理**: 理解实体之间如何连接，并利用这种理解完成更高阶目标的过程。

**示例**: 对树木到长椅的距离进行排序——需要比较实体（树和长椅）之间的**关系**（距离），而不是单独推理每个实体的属性（位置）。

### 现有架构的局限

| 架构 | 优势 | 局限 |
| --- | --- | --- |
| LSTM | 信息打包在共同的隐藏向量中 | 分隔化和关系推理可能困难 |
| 记忆增强网络 (DNC等) | 槽式记忆矩阵解决分隔化问题 | 记忆编码后难以相互交互 |
| 注意力机制 | 移除局部性偏置 | 但不是显式为记忆交互设计的 |

## Relational Memory Core (RMC)

### 设计原则

1. 提供架构骨架使模型能**分隔化**信息
2. 学习计算分隔化信息之间的**交互**

### 核心机制：多头点积注意力 (MHDPA)

假设已有记忆矩阵 $M$，每行 $m_i$ 是一个分隔化的记忆槽。

**注意力计算**:

$$A_\theta(M) = \text{softmax}\left(\frac{MW^q(MW^k)^\top}{\sqrt{d_k}}\right)MW^v$$

其中 $\theta = (W^q, W^k, W^v)$ 是可学习参数。

**解释**:

- 每个记忆对所有其他记忆进行注意力
- 输出 $\widetilde{M}$ 是 $M$ 的更新提议
- 每个 $\widetilde{m}_i$ 包含来自其他记忆 $m_j$ 的信息
- 模型学习如何在记忆之间传递信息

### 多头机制

使用 $h$ 组独立的 $(W^q, W^k, W^v)$，每个头可以：

- 让一个记忆向不同目标共享不同信息
- 即使只有单个记忆槽，也能通过多头实现信息分隔化

### 编码新记忆

通过简单修改将新输入 $x$ 融入记忆：

$$\widetilde{M} = \text{softmax}\left(\frac{MW^q([M;x]W^k)^\top}{\sqrt{d_k}}\right)[M;x]W^v$$

其中 $[M;x]$ 是行拼接。查询只来自 $M$，键和值来自 $[M;x]$，因此输出维度保持不变。

**关键**: 同一个注意力操作同时处理记忆交互和新信息编码。

### 嵌入到 LSTM

将记忆矩阵 $M$ 解释为 LSTM 的 cell state 矩阵，引入门控机制：

$$m_{i,t} = \sigma(f_{i,t} + \tilde{b}^f) \circ m_{i,t-1} + \sigma(i_{i,t}) \circ g_\psi(\widetilde{m}_{i,t})$$

$$h_{i,t} = \sigma(o_{i,t}) \circ \tanh(m_{i,t})$$

其中 $g_\psi$ 是行级 MLP（带 layer normalization）。

### 可调参数

| 参数 | 说明 |
| --- | --- |
| 记忆数量 | $M$ 的行数 |
| 记忆大小 | 每行的维度 |
| 注意力头数 | 独立的查询/键/值集数 |
| 注意力步数 | 每个时间步的注意力迭代次数 |
| 门控方式 | 单元级或记忆级门控 |

**重要**: 参数在所有记忆槽间共享，可以调整记忆数量而不影响参数量。

## 实验任务

### 1. $N^{th}$ Farthest 任务

专门设计来测试时序关系推理能力：

- **输入**: 随机向量序列 + 向量标签
- **问题**: "第 $n$ 远离向量 $m$ 的向量是哪个？"
- **要求**:
  - 计算所有成对距离关系（参考向量可能在记忆中或尚未出现）
  - 隐式排序这些距离
  - 必须排序**距离关系**，而非向量本身

### 2. 程序评估 (Learning to Execute)

| 类别 | 示例 |
| --- | --- |
| Addition | `print(53+97)` → `150` |
| Control | `for i in range(3): x+=2` → `6` |
| Full Program | 完整程序片段 |
| Memorization | 复制、反转、加倍序列 |

### 3. Mini Pacman (带视口)

- 智能体只能看到 $5 \times 5$ 视口
- 需要在**记忆中**预测幽灵动态
- 记住哪些食物已被吃掉

### 4. BoxWorld (带视口)

- 像素级组合推理任务
- 需要推理钥匙-锁颜色关系
- 选择正确的钥匙-锁序列到达宝石

### 5. 语言建模

- WikiText-103 (~100M tokens)
- Project Gutenberg (~180M tokens)
- GigaWord v5 (~4B tokens)

## 实验结果

### $N^{th}$ Farthest

| 模型 | 最佳准确率 |
| --- | --- |
| LSTM | <30% |
| DNC | <30% |
| **RMC** | **91%** |

**注意力分析发现**:

- 参考向量 $m$ 出现前：信息被写入 1-2 个记忆槽
- 参考向量 $m$ 出现后：所有记忆槽优先关注写入 $m$ 的那些记忆

### 程序评估

| 模型 | Add | Control | Program | Copy | Reverse | Double |
| --- | --- | --- | --- | --- | --- | --- |
| LSTM | 99.8 | 97.4 | 66.1 | 99.8 | 99.7 | 99.7 |
| EntNet | 98.4 | 98.0 | 73.4 | 91.8 | **100** | 62.3 |
| DNC | 99.4 | 83.8 | 69.5 | **100** | **100** | **100** |
| **RMC** | **99.9** | **99.6** | **79.0** | **100** | **100** | 99.8 |

RMC 在所有任务上都表现最佳或并列最佳。

### Mini Pacman

| 设置 | LSTM | RMC |
| --- | --- | --- |
| 带视口 | 550 | **677** |
| 完整观测 | 598 | **1159** |

### BoxWorld

| 模型 | 成功率 |
| --- | --- |
| ConvLSTM | 73% |
| **RMC** | **98%** |

### 语言建模 (Perplexity ↓)

| 模型 | WikiText-103 | Gutenberg | GigaWord |
| --- | --- | --- | --- |
| LSTM | 34.3 | 45.5 | 43.7 |
| Gated CNN | 37.2 | - | - |
| Quasi-RNN | 33 | - | - |
| **RMC** | **31.6** | **42.0** | **38.3** |

在三个数据集上均达到**当时最先进水平**，相对改进 5-12%。

## 语言建模配置

最佳配置（WikiText-103）：

| 参数 | 值 |
| --- | --- |
| 总记忆单元 | 2500 |
| 注意力头数 | 4 |
| 记忆数量 | 1 |
| MLP 层数 | 5 |
| 注意力块数 | 1 |

**有趣发现**: 语言建模使用单个（大）记忆槽效果最佳，而关系推理任务需要多个记忆槽。

## 关键发现

### 记忆槽 vs 注意力头的权衡

- **多记忆槽**: $N^{th}$ Farthest 任务必需（8或16个记忆优于1个）
- **单记忆+多头**: 单记忆时，更多头(8或16)优于1个头
- **语言建模**: 单个大记忆效果好（需要大量参数）
- **程序评估**: 中等配置（4槽4头）效果最好

### 上下文长度分析

RMC 在短上下文时性能下降较小：

- 100 步上下文：RMC 下降 1 perplexity，LSTM 下降 5
- 说明 RMC 更好地捕获短期关系

## 与相关工作的联系

### 与 Transformer 的关系

- 都使用多头点积注意力
- **区别**: RMC 在**单个时间步**的记忆间应用注意力，而非跨所有历史表示
- Transformer 的计算随时间步数增长，RMC 保持恒定

### 与 Relation Networks 的关系

- 同一作者团队的后续工作
- Relation Networks 处理空间实体对
- RMC 将关系推理引入时序/记忆域

### 与 DNC/NTM 的关系

- 都使用外部记忆矩阵
- **区别**: RMC 允许记忆之间显式交互

## 核心贡献

1. **问题发现**: 揭示现有记忆架构在时序关系推理上的局限
2. **架构创新**: 提出 RMC，通过 MHDPA 实现记忆交互
3. **多任务验证**: 在 RL、程序评估、语言建模上均有改进
4. **分析洞察**: 记忆槽数量和注意力头数的权衡是任务相关的

## 局限性与讨论

**局限性**:

- 难以与 Transformer 等在线设置中的模型直接比较
- 记忆槽数与头数的最优配置是任务相关的，需要调参
- 注意力分析的解释有限（单次注意力后信息可能高度分布）

**未来方向**:

- 混合纯循环方法与随时间增长的方法
- 先无损积累记忆一段时间，再学习压缩到循环核心
