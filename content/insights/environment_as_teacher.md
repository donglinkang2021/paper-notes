# 环境即教师：从纯自博弈到环境驱动的发现

纯自博弈方法（R-Zero、SRT）的失败揭示了一个根本问题：模型在自我封闭的循环中无法获得新知识，只能重组已有知识。SPICE 和 Absolute Zero 提出了范式转变——将外部环境作为知识来源和验证器，让模型在与环境交互中发现问题、学习知识。这与用户笔记中的核心愿景"让环境介入地进行数据合成"完美契合。

## 环境的三种角色

**角色一：知识库（SPICE 的文档语料库）**

SPICE 用 20,000 文档作为环境，Challenger 从文档中挖掘内容生成问题。这打破了纯自博弈的信息对称性——Challenger 看到文档，Reasoner 只看到问题。文档提供的是"近乎无穷的多样性"，这是模型自身无法生成的。

关键设计：
- 问题必须 100% 自包含，不引用原文档，迫使 Challenger 提炼和合成知识
- 需要多步推理，不能通过查找单个事实回答
- 综合文档中的多个概念

实验结果：相比无语料库的 R-Zero，SPICE 总体提升 +7.9%，稳定训练 640 轮（R-Zero 仅 5 轮后退化）。

**角色二：验证器（Absolute Zero 的代码执行器）**

Absolute Zero 用 Python 执行器作为可验证环境。模型提出代码任务（程序、输入、输出三元组），执行器验证正确性。这避免了神经奖励模型的 reward hacking 问题——代码要么能运行，要么不能，没有中间地带。

三种推理模式：
- 演绎：给定程序和输入，预测输出
- 溯因：给定程序和输出，推断输入
- 归纳：给定输入输出样例，合成程序

实验结果：从单个恒等函数种子开始，代码平均 +5.0，数学平均 +15.2，超越使用 57k-484k 数据的方法。跨域泛化惊人——在代码任务上训练，数学能力提升 15.2 分。

**角色三：语义锚点（R-Few 的人类数据）**

R-Few 用 1-5% 人类数据作为"锚点"，通过 few-shot 示例软引导问题生成。这不是传统意义的训练数据，而是防止概念漂移的参考系。

关键机制：
- 随机采样 k ∈ {0,1,...,5} 个示例作为 in-context examples
- k=0 时退化为 R-Zero，保留开放式探索能力
- k>0 时软引导，保持语义一致性

实验结果：仅 5% 数据达到 20 倍数据量方法的性能，多样性全程稳定，问题长度保持一致。

**角色四：交互式环境（Self-Challenging Agents 的工具环境）**

SCA 让智能体在多轮工具使用场景中主动探索环境，通过与环境交互收集信息后生成任务。这是环境从"静态知识库"到"动态交互空间"的演进。

关键设计：
- 挑战者通过调用工具（如购物网站导航、客服系统）收集环境信息
- 基于交互轨迹生成 Code-as-Task（指令 + 验证函数 + 示例解决方案 + 失败案例）
- 严格的自动过滤（5.2% 通过率）确保任务质量

实验结果：在部分可观察环境（Web Browsing、Retail）中显著优于仅从 API 文档生成任务的 PAE 方法，自我改进设置下成功率翻倍（12.0% → 23.5%）。

## 信息不对称的关键作用

SPICE 的核心创新在于打破纯自博弈的信息对称性。在 R-Zero 中，Challenger 和 Solver 都只能访问模型内部知识，形成零和博弈。在 SPICE 中，Challenger 看到文档但 Reasoner 看不到，创造了真正的信息梯度。

这解释了为什么 SPICE 能稳定训练 640 轮而 R-Zero 仅 5 轮：
- R-Zero：Challenger 生成的问题来自模型已知知识，Solver 学习的也是已知知识，快速饱和
- SPICE：Challenger 从文档中提炼新知识，Reasoner 被迫学习文档中的概念，持续获得新信号

**SCA 的主动探索扩展**：

SCA 进一步扩展了信息不对称的概念——不仅 Challenger 看到环境信息，而且 Challenger 需要主动探索才能获取信息。这在部分可观察环境中至关重要：
- PAE（被动生成）：仅从 API 文档生成任务，在部分可观察环境中只能生成模糊任务
- SCA（主动探索）：通过与环境交互收集信息后生成精确任务，在 Web Browsing 环境中性能提升显著

## 推理模式的涌现

SPICE 训练过程中，Reasoner 的推理能力显著进化：

**早期训练**（直觉猜测）：
"月球在 374,000 km，星星更远，可能 1000 倍？所以 374,000,000 km"

**后期训练**（结构化多步推理）：
1. 识别给定信息
2. 理解完美日食条件（角大小相等）
3. 建立方程：$\frac{3,475}{374,000} = \frac{1,391,000}{d}$
4. 求解：$d = 149,708,489$ km
5. 匹配最接近选项
6. 验证计算

这种从直觉到结构化推理的演变，证明了环境驱动的学习可以涌现出复杂的认知能力。

## Evidence

- [SPICE](../knowledge/summary_spice_self_play_corpus.md): 20,000 文档语料库，相比无语料库 +7.9%，稳定训练 640 轮，推理模式从直觉猜测演化到结构化多步推理
- [Absolute Zero](../knowledge/summary_absolute_zero_reasoning.md): Python 执行器验证，从单个恒等函数种子开始，代码 +5.0，数学 +15.2，跨域泛化惊人
- [R-Few](../knowledge/summary_r_few_guided_self_evolving.md): 1-5% 人类锚点，用 5% 数据达到 20 倍数据量方法的性能，防止概念漂移和多样性崩溃
- [Self-Challenging Agents](../knowledge/summary_self_challenging_agents.md): 主动探索工具环境，Code-as-Task 严格过滤（5.2% 通过率），自我改进成功率翻倍（12.0% → 23.5%）

## Implications

"环境即教师"范式为用户笔记中的核心愿景提供了实现路径："让环境介入地进行数据合成"、"独立发现问题、独立解决问题、独立使用工具验证答案"。

Absolute Zero 已经实现了完整循环：
1. **独立发现问题**：Proposer 生成代码任务
2. **独立解决问题**：Solver 编写代码
3. **独立使用工具验证**：Python 执行器验证正确性

SPICE 展示了如何将这个范式扩展到更广泛的领域——用文档语料库替代代码执行器。但 SPICE 的验证仍依赖神经模型（GPT-4o 进行等价性检查），不如代码执行器可靠。

**Group 5 的新证据**：

SCA 证明了主动环境探索的重要性——在部分可观察环境中，被动地从文档生成任务（PAE）远不如主动与环境交互后生成任务（SCA）。这为"独立发现问题"提供了更强的实现路径：
- 不仅从静态知识库中提炼问题（SPICE）
- 还要通过主动探索动态环境发现问题（SCA）
- 用可执行代码表达任务的所有组件（Code-as-Task），实现跨领域的可验证问题合成

未来方向：
1. **多环境融合**：代码执行器（可验证） + 文档语料库（知识丰富） + 工具环境（交互式） + 人类锚点（语义稳定）
2. **环境发现**：不仅在给定环境中学习，还要学会发现和构建新的验证环境
3. **可验证环境的扩展**：形式化证明系统、物理模拟器、真实世界交互
4. **主动探索策略**：学习如何高效探索环境以发现有价值的问题（结合 SCA 的主动探索 + SPICE 的文档挖掘）

关键洞察：环境不是被动的验证器，而是主动的知识来源。模型与环境的交互不是"测试"，而是"学习"。SCA 进一步证明：在部分可观察环境中，主动探索比被动观察更能发现有价值的问题。这是从"模仿人类数据"到"通过经验积累知识"的范式转变，类似人类学习方式。
